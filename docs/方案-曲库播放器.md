# MYBIT 曲库播放器 · 实施方案

> 目标：板子用 **A / B 键选歌**，曲目列表可编辑，歌曲文件可**上传 / 删除**。
> 全部参数来自 2026-11-10 对本机 COM3 上这块板（npython v1.06.5 / ESP32 / MicroPython 1.13）的**真机实测**，不是照文档抄。

---

## 一、先把"能不能放外部歌曲"钉死（实测结论）

| 能力 | 实测结果 | 对方案的影响 |
|---|---|---|
| `music.play(元组)` | ✅ 只接受 **字符串元组**，如 `('c4:2','e4:2','r:4')` | 这就是"歌"的载体，可任意自定义 |
| `music.play([('C4',4),...])` | ❌ **硬崩** `LoadProhibited / Guru Meditation` 自动重启 | 绝不能喂 tuple 列表/数字，必须严格校验 |
| 音名语法 | `c4` / `c#5` / 省略八度 `e`（继承前一个八度）/ 休止 `r:4`、`0:4` | 谱面格式由此确定 |
| 时长单位 | `:n` = n tick；**bpm120 时 1 tick = 125 ms**（实测 `:1`→130ms、`:4`→504ms、`:8`→1006ms），bpm240 时长减半 | 时长可精确换算 |
| 播放特性 | **阻塞**，播完才返回；`music.stop()` 只能在两段之间调用 | 必须**分段播放**才能做到"按 A/B 立刻切歌" |
| `machine.I2S` | ❌ 不存在 | 无数字音频输出通路 |
| `machine.DAC` | ✅ `DAC(Pin(25)).write()` 可写 | 但见下条 |
| `Timer` 回调 | period 最小 **1 ms** → 实际回调上限 ~1000 Hz | 1 kHz 采样率放不了 PCM，**软播 WAV 不可行** |
| 存储 | 文件系统 2 MB，**空闲 2,023,424 B** | 音符谱每首 0.1–1 KB，能放上千首 |
| RAM | 空闲 82 KB；载入 microdot 后约 44 KB | 上传必须流式写盘，不能整体读进内存 |
| 并发设施 | `_thread` ✅、`select` ✅、`settimeout(0)` ✅；`uasyncio` ❌ | Web 服务用线程跑，主线程专心按键+播放 |
| 内置曲 | 27 首 melody 已全部导出到 `songs/*.mel`（NYAN 106 音、歌唱祖国 194 音…） | 开箱即有曲库 |

**结论一句话**：这块固件**放不了 MP3/WAV/人声**（没有 I2S，Timer 也喂不上采样率），但能放**任意单声部旋律**，音色是经典方波"电子琴"。所以"外部歌曲"= 把歌转成 **`.mel` 音符谱文件**；上传/删除/排序就是对 `songs/` 里文件的操作。想听原曲音质只有一条路（加 DFPlayer 模块，见第七节）。

## 二、成品形态

```
      ┌──────────────────────────┐
      │ [03/27] NYAN             │  ← 行1 序号/总数 + 曲名
      │ PLAY ▶      00:12/01:44  │  ← 行2 状态 + 进度
      │ bpm120  loop:OFF         │  ← 行3 参数
      │ AP: MYBIT-SONG           │  ← 行4 网络提示
      │ IP: BOARD_AP_IP          │  ← 行5 网页地址
      └──────────────────────────┘
              A键 ◀       ▶ B键
```

三套操作界面共用同一份曲库：
1. **按键**（离线可用）：A 上一首、B 下一首，选中即播
2. **网页**（手机/电脑浏览器）：列表、上传、删除、改名、调序、远程点播
3. **串口命令行**（PC，`songtool.py`）：批量灌曲、批量删除、远程点播

## 三、曲库格式 `.mel`（板子唯一认的格式）

```text
# name: 晴天
# bpm: 96
# loop: 0
c4:2 d:2 e:4 r:2 f#5:8 a4:4 g:2 f:2 e:8
```

规则：

| 记号 | 含义 |
|---|---|
| `# name:` | 显示名（可中文，UTF-8） |
| `# bpm:` | 速度，默认 120；**1 tick = 60/(bpm×4) 秒** |
| `# loop:` | 1 = 循环播放 |
| `c d e f g a b` | 音名；大写小写都收（统一转小写） |
| `c#5` `bb4` | 升/降号（`#`、`b` 紧贴音名） |
| `c5` / `c` | 带八度 / 省略则继承上一个音的八度，首个默认 4 |
| `:n` | 时长 n tick；省略 = 1 tick |
| `r:n` `0:n` | 休止 n tick |
| 空格 / 换行 / 逗号 | 分隔符，随意 |

**安全校验（防崩溃）**：每个 token 必须匹配
`^(r|0|[a-g][#b]?[0-8]?)(:\d{1,3})?$`（小写后），不匹配直接丢弃并记日志，绝不送进 `music.play`。

## 四、板端结构

```
/                    根目录
├─ boot.py           （改造：见 4.5）
├─ main.py           player.py 主程序
├─ microdot.py       已上传可用（46 KB）
├─ wifi.txt          可选，两行：SSID / 密码
└─ songs/
   ├─ order.txt      可选，一行一个文件名，决定播放顺序
   ├─ nyan.mel
   ├─ ode.mel
   └─ ...
```

### 4.1 按键表

| 操作 | 功能 |
|---|---|
| A 单击 | 上一首（**切到就播**，循环到底） |
| B 单击 | 下一首（**切到就播**） |
| A 长按 ≥700 ms | 播放 / 暂停 |
| B 长按 ≥700 ms | 循环模式 开/关 |
| A+B 同按 | 立即停止，并在 OLED 上停留显示当前 IP 3 秒 |

`button.get_a()/get_b()` 返回 0/1（真机已验证）。用 30 ms 采样 + 边界消抖 + 计时判长按。

### 4.2 播放调度（关键设计）

`music.play` 阻塞且不可中断，所以**分段播放**：

```
读谱 → token 列表
while 还有 token:
    取一段（累计时长 ≤ 400 ms 且 ≤ 8 个 token）
    music.play(这一段)
    段内每 60 ms 轮询按键 → 有切歌/暂停立刻 break（最多等 400 ms）
```

- 切歌响应延迟：≤ 400 ms（实测体验够快）
- 进度条按已播 tick 估算，误差 < 5 %
- 线程安全：Web 线程只写 `cmd = ('play', 'nyan.mel')` 这类**命令元组**，主循环在段间取走执行，不直接操作播放

### 4.3 Web 接口（microdot，跑在 `_thread` 里）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 曲库管理页（列表 + 上传框 + 每行按钮） |
| GET | `/api/list` | JSON：`[{"i":1,"f":"nyan.mel","name":"NYAN","bpm":120,"ticks":206,"sec":215}]` |
| POST | `/upload` | multipart，字段 `file`，**流式写盘**（512 B/次），只收 `.mel`，≤ 64 KB，先写 `xxx.tmp` 再 rename |
| GET | `/rm?f=nyan.mel` | 删除（同时从 order.txt 移除） |
| GET | `/rename?f=old.mel&n=新名字` | 改文件 + 改 `# name:` |
| GET | `/order?f=nyan.mel&dir=up\|down` | 在 order.txt 里上移/下移 |
| GET | `/play?f=nyan.mel` | 远程点播（= 按 B 的效果） |
| GET | `/stop` | 停止 |

页面全部内嵌在 `player.py` 里（约 4 KB HTML），不依赖外部 CDN，断网也能用。

### 4.4 网络：不依赖任何外部热点

启动顺序：
1. 有 `/wifi.txt` → `wifi.connect(ssid, pw)`，成功则 OLED 显示 `STA: 192.168.x.x`
2. 失败或无配置 → `wifi.enable_AP("MYBIT-SONG", "YOUR_WIFI_PASSWORD")`，手机连这个热点，浏览器打开 **BOARD_AP_IP**

> 这样在教室/宿舍没有可用 2.4G 热点时照样能传歌。`enable_AP()` 在本板已实测成功。

### 4.5 必须先改造的 `boot.py`

原始 `boot.py` 逻辑：**上电瞬间 A 键为高电平 → `os.remove('/main.py')`**。
而我们的播放器把 A 当"上一首"，用户插电时顺手按着 A 就会把播放器删掉（这也是之前"程序莫名消失"的原因）。

改法：把删除条件从"上电瞬间 A 按下"改成"**上电时按住 A ≥ 3 秒**进入救援模式（先把 main.py 备份成 main.bak 再删）"，否则正常启动。原文件已备份在 `_board_backup/boot.py`。

## 五、PC 端工具 `songtool.py`

一条命令覆盖"造歌 + 灌歌 + 管歌"：

```bash
python songtool.py list                          # 板上有哪些歌
python songtool.py push songs\ode.mel            # 上传（单个或整个目录）
python songtool.py push songs\ -r                # 递归整目录
python songtool.py rm ode.mel                    # 删除
python songtool.py order                         # 打印当前顺序
python songtool.py play nyan.mel                 # 远程点播
python songtool.py midi 晴天.mid -o qingtian      # MIDI → .mel
python songtool.py jianpu 简谱.txt -o test        # 简谱文本 → .mel
python songtool.py selftest                      # 一键跑完验收清单
```

转换器（本机跑，板子不参与）：

1. **简谱**：`1 2 3 4 5 6 7` + `-`(延长) + `.`(附点) + `#`/`b` + `'`(高八度) + `,`(低八度) + `0`(休止)，`|` 作小节线忽略；1 拍 = 4 tick
2. **MIDI**（`pip install mido`，纯 Python 无编译）：自动挑"音符最多、平均音高最高"的轨道当主旋律，按 tempo 量化到 1/16 拍，短于 80 ms 的音符丢弃
3. **音频**（可选，`numpy` 即可）：帧长 2048 / 跳 512 自相关求基频 → 转半音 → 中值滤波去抖 → 合并同音 → 输出。**只还原主旋律**，和弦、伴奏、人声一律丢失，节奏靠 librosa 可选增强

## 七、音质天花板，和"真要放 MP3"的硬件路线

本固件能做到的极限：**单声部方波旋律**，能听出歌，但没有和弦、没有伴奏、没有人声。

真要放原曲（MP3/WAV），只有一条现实路径 —— 加 **DFPlayer Mini（YX5200）串口 MP3 模块**（约 15 元）：

```
板子 PINS[x] TX ──► 模块 RX         模块 SPK1/SPK2 ──► 外置喇叭
板子 GND     ──► 模块 GND
板子 5V      ──► 模块 VCC
TF 卡（FAT32）：/01/001.mp3、/02/002.mp3 …
```

控制协议（10 字节帧，`7E FF 06 CMD 00 00 PARAM_H PARAM_L EF`）：`03` 指定曲目、`0D` 播放、`0E` 暂停、`06` 设音量、`0F` 停止。
改造后按键/网页逻辑不变，只是"播放"从 `music.play` 换成串口发帧；曲目列表来自 `/songs/index.txt`（序号 → 名称），**MP3 文件得插读卡器拷**（模块只读不写）。
这条路音质是和原曲一致的，代价是多一个模块、多一套供电和接线，且传歌要拔卡。

## 九、风险清单

| 风险 | 处置 |
|---|---|
| 传错类型给 `music.play` → 板子硬崩重启 | 入谱前正则白名单校验，非法 token 丢弃 |
| `boot.py` 上电删 `main.py` | 改成长按 3 秒才进救援模式 |
| 播放阻塞导致按键无响应 | 分段播放（≤400 ms/段） |
| 上传大文件爆 RAM | 512 B 流式写盘 + 64 KB 上限 + tmp→rename |
| 文件系统写满（2 MB） | 上传前查 `statvfs` 余量，不足直接 507 |
| Web 线程与播放线程抢 FS | 上传只在主线程空闲段提交 rename；播放先把谱读进内存 |
| `#` 在 URL/文件名中需转义 | 文件名只允许 `[A-Za-z0-9_-]`，显示名放 `# name:` 里 |
| 中文名显示乱码 | OLED 用固件自带字体，中文可能不支持 → 曲名一律显示文件名，中文名保留在网页端 |
