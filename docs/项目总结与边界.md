## 撞到的硬墙

这些是**软件层面解决不了**的，再优化也没用。

### 1. 内存：111 KB 堆，2 秒录音上限

```
3 秒录音 → 49196 字节，需 49KB 连续块 → MemoryError
2 秒录音 → 32812 字节，需 32KB     → 稳定
```

**原因**：堆碎片。总量够（75KB 可用），但拿不到连续 4096 字节块。

**试过的办法**：
- 多次 `gc.collect()`（6~16 轮）：有帮助但有限
- 清空显示缓冲：帮助很小
- 分块处理：录音 API 不支持

**结论**：硬件限制，除非换板子。

### 2. TLS：板子连不了 HTTPS

```
api.deepseek.com:443 → ussl.wrap_socket → OSError [Errno 12] ENOMEM
```

**原因**：TLS 握手需要临时分配几十 KB 做密钥交换和证书链验证，板子给不出。

**绕法**：走中转服务器（纯 HTTP）。

### 3. 流式录音：固件不支持

```python
audio.record('x.wav', 2)   # 阻塞 2 秒，一次性生成整个文件
```

**没有** `record_start()` / `read_chunk()` 这类流式 API。

**试过**：`_thread` 不调度（`start_new_thread` 后不开线程）。

**影响**：无法边录边传，无法实现自动断句。

### 4. 麦克风信号弱

```
真实语音幅度：±330（正常应 ±10000）
直流偏置：   -8620
```

信号只有正常值的 3%，必须靠服务器端放大 20~30 倍才能识别。

**能工作的条件**：凑近（10~20cm）说话，2 秒内说完。

### 5. `f.read()` 行为异常

```
49196 字节的文件，f.read(512) 循环只读出 44 字节就 EOF
```

**影响**：上传时的 `Content-Length` 必须用 `os.stat()` 拿，不能靠读文件计数。

### 6. raw REPL 更费内存

同样 `free` 值下，raw REPL 执行脚本时录音失败，普通 REPL 成功。

**影响**：调试录音相关代码必须用普通 REPL 逐行发。

### 7. 没有 I2S / DAC 音频输出

```
machine.I2S → 不存在
machine.DAC → 存在，但 Timer 上限 1kHz，喂不上采样率
```

**影响**：放不了 MP3/WAV，只能单音旋律或用外置模块。

## 如果继续做

按投入产出排序。

### A. 换板子（收益最大）

**ESP32-S3 + 8MB PSRAM**：

| 能力 | 现在 | 换了之后 |
|---|---|---|
| 录音时长 | 2 秒 | 30 秒+ |
| 流式录音 | ❌ | ✅ I2S 支持 |
| HTTPS 直连 | ❌ | ✅ 内存够 |
| 音频输出 | ❌ | ✅ I2S DAC |
| 板子独立跑 whisper | ❌ | ❌（还是不够，但能做 VAD）|

代价：几十到两百元，要重新适配固件。

### B. 给板子申请 MAC 白名单

找网络中心把 `20:43:A8:E2:C7:9C` 绑到你的账号：

- 现在：连 HZCU 后要自己认证
- 之后：连上就能用，不用认证代码

**收益**：省掉认证环节，稳定性略提升。不改代码。

### C. 加外置语音合成模块

UART1 已经预留（`PINS[0]` / `PINS[1]`），代码里 `speak()` 已实现帧格式：

```
7E | 帧长(2B) | 01 00 03 | 03 E8 | 数据长 | 文本 | 校验 | EF
```

买个 SYN6288 或类似模块（20~50 元）就能让板子说话。

**收益**：从「只能看屏幕」变成「能听能说」。

### D. 手机做中继

板子做 AP，手机连上去，手机开热点共享给板子：

- 绕开校园网认证
- 板子跟着手机走

**代价**：手机耗电，且要写个转发 app。

### E. 更好的唤醒词

现在要按 A 键。可以试：

- 录音 2 秒，服务器端做关键词检测（「小特小特」）
- 检测到就直接进入问答

**问题**：板子必须一直录音，内存和功耗都撑不住。

## 这套东西的可迁移性

**不完全绑定这块板子。** 可以复用的部分：

| 文件 | 可复用性 |
|---|---|
| `relay_server.py` | ⭐⭐⭐ 完全通用，任何设备都能接 |
| `pc_agent.py` | ⭐⭐⭐ 完全通用，不限于板子触发 |
| `taskqueue.py` | ⭐⭐⭐ 通用任务队列 |
| `relay.py` | ⭐⭐ 改 SRV_HOST 就能用 |
| `hzcu.py` | ⭐ 只对 HZCU 校园网有效 |
| `ai_voice.py` | ⭐ 绑定 npython 的 OLED/按键 API |

**换句话说**：服务器端和电脑端是通用的，换任何能发 HTTP 的设备（另一块 ESP32、树莓派、旧手机）都能接进来。

## 一句话总结

**这块板子的软件潜力基本挖尽了。**

它做不了：高清音频、实时视频、复杂 AI 推理、长时间录音、HTTPS 直连。

它能做而且做得不错：传感器采集、简单显示、按键交互、单音音乐、简单的网络通信。

**用它的正确姿势**是当「端点」——采集数据、显示结果、接受指令，把重活都丢给服务器。现在的架构就是这样，也是它能跑出这个效果的原因。

想再往上提升，只能换硬件。
